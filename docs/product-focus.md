# Product focus after user feedback — 17 September 2026

## Diagnosis

The previous release passed technical checks but spread attention across a catalog, uncertainty labels, file tools and planning helpers. Passing tests did not establish a compelling product proposition. The user explicitly requested removing excess and reconsidering the idea; this supersedes the earlier presentation freeze.

A current evaluation of the demo profile shows UW–Madison, Waterloo and Georgia Tech with no unknown evaluated rule branches. Waterloo and Georgia Tech nevertheless have INDETERMINATE states because remaining actions/route verification are unresolved. This is distinct from missing institutional rules. None of this verifies total future cost or guarantees admission.

## Implemented simplification

- The main map starts with UW–Madison, Waterloo and Georgia Tech. This is an explicitly selected initial product cohort, not a global ranking and not a guarantee that every user fits these universities. Profile-dependent gaps remain visible.
- Other research programs are available through an explicit toggle; the dataset and original evidence are not deleted or falsified. Existing shortlist entries remain accessible.
- Backup/import/recovery move under Profile tools. Named hypothetical scenarios remain in the primary flow.
- Calendar, optional personal tasks and question drafting move behind a single secondary disclosure. The roadmap and next action remain prominent; optional data is preserved.
- Cards distinguish remaining user steps from unknown rule branches without rewriting backend states.
- The hero asks which change opens a new path. This is a focused entry point into the existing simulation, not a claim that an automatic best-action optimizer was implemented.

## Brainstorm — proposed directions, not new shipped capabilities

### 1. PathShift Plan B — stress-test an admission plan (recommended)

Promise: Understand which routes survive if a test result or timing changes, and choose a concrete fallback.

Demo: a student chooses three target programs; a hypothetical exam changes; the affected requirements and tasks are shown; the student compares an alternative route and adopts the next real action. Show both routes that improve and routes that remain closed. Clearly label hypothetical results and unverified facts.

Why this can make a stronger demonstration: judges observe a cause, a consequence and a decision in one short story. It builds on the existing deterministic engine rather than requiring a broad unreliable catalog. Do not claim a probability of success, a guaranteed backup institution, or precise preparation time.

Before claiming this full concept: add an explicit Plan A/Plan B presentation and verify both upward and downward perturbations and delayed-result cases. Those are future implementation choices, not features shipped by this cleanup.

### 2. Highest-value next action

Promise: compare actions by the number of known requirements they resolve across the student's targets.

Strength: concrete, measurable result from the existing rule traces. Risk: calling an action “best” requires declared preferences and supported time/cost assumptions. Do not invent those. This is a useful component of Plan B, not another standalone product.

### 3. Application failure prevention

Promise: detect a missed requirement, an impossible dependency or a wrong intake before the user acts.

Strength: trustworthy and immediately useful. Risk: a warning dashboard can reproduce the current problem of many blockers and little hope. Use a small set of actionable findings inside the route, rather than making a large separate dashboard.

## Competitive grounding

Public first-party pages checked during this review:

- ApplyBoard already presents personalized program matching: https://www.applyboard.com/blog/program-matcher
- Cialfo already presents university fit and intelligent matching: https://www.cialfo.co/for-students/right-fit-universities

These pages support that catalog + profile matching is an established product pattern. They do not prove that no competitor has simulations or fallback planning. Do not claim global uniqueness or guaranteed hackathon success.

## Stop adding

No chatbot as decoration, invented admission percentages, extra countries without evidence, compulsory project manager, or broad automatic scraping pipeline before defense. Keep one coherent story and the sources needed to support it.
