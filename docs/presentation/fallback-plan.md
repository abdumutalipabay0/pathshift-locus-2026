# PathShift — резервный план защиты

## Если медленно отвечает ИИ

ИИ не нужен для центрального примера IELTS. Не запускать его во время живой защиты. Показать заранее сохранённый черновик резюме и сказать:

> «Этот ответ получен до демонстрации. Пользователь проверяет исходную цитату перед сохранением. Центральную проверку требований выполняет отдельная логика правил».

После этого сразу перейти к UW–Madison.

## Если сценарий не пересчитывается за 8 секунд

1. Не нажимать кнопку повторно.
2. Сказать: «Сеть задерживает пересчёт. Покажу проверенный результат на слайде».
3. Переключиться на слайд 6: фактический результат 6.0, гипотеза 6.5, выполнена только языковая проверка.
4. Открыть **«Мои задачи»** и продолжить с ближайшего действия.

## Если сеть пропала полностью

Сказать дословно:

> «Покажу запись той же опубликованной версии. Рабочая ссылка и исходный код остаются в материалах».

Запустить локальное демо-видео с момента 0:12. Не называть запись живым сайтом. После фрагмента 1:55 перейти на слайд 7, чтобы сохранить общий тайминг.

## Если не открывается даже видео

Использовать локальный PDF и три кадра:

1. `02-student-story.png` — интерес и опыт Аружан.
2. `05-personal-requirements.png` — IELTS 6.0 против 6.5 и источник.
3. Слайд 6 — отдельный сценарий и неизменный профиль.

Финальное действие назвать словами: **«Проверить список документов UW–Madison»**. Не использовать `08-next-step.png` как доказательство этой фразы, пока в демопрофиле есть UBC.

## Что хранить локально на ноутбуке

- Финальный PPTX и PDF.
- Финальное демо-видео в MP4.
- Папку `docs/presentation/screenshots/`.
- Этот run of show и текст речи в PDF или распечатке.
- Ссылку на сайт и репозиторий в простом текстовом файле без паролей.
