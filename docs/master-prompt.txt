Да. Я сперва посмотрел актуальные рекомендации OpenAI по Codex и забрал оттуда именно то, что нам полезно.

Для большой задачи OpenAI рекомендует **сначала Ask Mode → implementation plan → потом Code Mode**, формулировать задачу примерно как хороший GitHub Issue: цель, конкретные компоненты, ограничения, expected behavior и проверки. Также полезно вынести постоянные правила в `AGENTS.md`.  Для больших agentic-проектов OpenAI отдельно отмечает, что лучше давать Codex **карту репозитория и структурированные docs**, а не один гигантский постоянно растущий `AGENTS.md`; edge cases и действия агента должны быть явно определены. 

Поэтому я сделал не просто «сделай сайт», а **implementation contract**.

**Как запускать:** сначала положи/дай Codex в контекст Case 2, Regulations и два Deep Research отчёта. Затем вставь промпт ниже в **Ask Mode**. После его плана переключаешься в **Code Mode** и говоришь: `Execute the approved plan end-to-end. Do not reduce scope unless blocked by a source-of-truth constraint.`

17. MINIMAL UNLOCK ENGINE
============================================================

Do not implement Minimal Unlock as a hard-coded string.

Algorithm:

1. collect failed verified HARD rules;
2. enumerate supported recourse actions;
3. remove immutable actions;
4. remove hard-lock violations;
5. remove timeline-infeasible actions;
6. simulate remaining action sets through the SAME rule engine;
7. keep non-dominated solutions;
8. return 1–3 minimal feasible paths.

Support alternative solutions.

Example:

English blocker may be resolvable via:
- IELTS threshold;
- TOEFL threshold;
- verified exemption;
- official conditional route.

Do not hide valid alternatives simply because one is easiest.

### Перед тем как отдать это Codex

**Один важный момент:** в prompt я специально **не переписал все десятки source URLs и весь Deep Research на 60k символов**. Это соответствует совету OpenAI не превращать agent context в один монолит; Codex должен иметь research как отдельный source-of-truth file и получать из master prompt карту того, *как им пользоваться*. 

То есть перед запуском я бы положил **полный последний Deep Research** в `docs/research/pathshift-data-freeze.md`, а предыдущий 50-вопросный research — в `docs/research/pathshift-decision-research.md`. Тогда Codex сможет сам читать точные URL, значения и rule trees, а этот master prompt будет управлять всей разработкой.

И да — **вот после этого уже можно реально стартовать разработку**. У нас больше нет проблемы «что вообще строить». Теперь задача — execution.
